# Independent review of APP_IMPROVEMENT_PLAN.md

Reviewed 2026-10-06 against source baseline `0732bb5` / v0.1.91, area reports and current proof logs. Review was read-only; this file is the only review artifact written.

## Decision

Approved with a few precision and execution-scope edits recommended. The roadmap is evidence-led, preserves the closed product decisions, separates confirmed defects from optional improvements and hypotheses, and mostly reuses existing helpers. I found no reason to reject its direction.

## Source and proof checks

- **O1, remote label draft file read:** confirmed. `labels:previewDraft` is registered with `expose()` and is RPC reachable; its validator only checks that `template` is an object. `labelsDocument` resolves draft image references through `previewImageSrc` → `assetDataUri`, which attempts an absolute path and reads any existing file into the returned data URI. The proof uses a mock sentinel, not a real file.
- **O2, export subfolder escape:** confirmed and reachable through the client export path. `exports:runForClient` makes a server temp root, then calls `runExport` with the stored profile unchanged; `runExport` joins `outputSubfolder` directly and creates/writes there. The client call does not pass `onExisting`, so the server uses `keepBoth`; that prevents replacing an already-present destination but does not prevent creating a new output outside `tmpRoot`. The server later walks only `tmpRoot`, so escaped files are left behind and are not returned to the client. The evidence supports an unintended server-side file-placement/write boundary, not arbitrary overwrite or code execution. `export.run` permission is required.
- **PO-1, brand rename collision:** confirmed. Name uniqueness checks raw names, while the move uses slugs; `A B` and `A&B` collide, as do `A 1` and `A-1`. The filesystem mover renames onto existing targets, and the DB path rewrite happens before the mover. The reported hashes/rows effect is credible and the mocked probe passes.
- **AI save/cancellation claims:** confirmed by `image-ai-evidence.log` and source. A failed output write can still lead to Done with no gallery row. Cancel removes an active task's slot while its provider promise remains live; the runner can then exceed configured concurrency and a late rejection can overwrite Cancelled. Repair accepts a task ID still in flight. The plan correctly preserves earlier durable results and does not promise reversal of provider charges.
- **Operations and Settings:** the component-harness logs support the stated stale selected cost (10 remains after backend changes to 22), realized margin mismatch (retail rounds to 0.02, actual margin is 50% while UI says 40%), connection failure shown as no history, and indefinite Settings Loading on rejected `getAll`.
- **Output proof status:** reread the updated `output-studios-proof.log`; all six assertions now pass. The earlier log failure was fixed before this review. Product/AI/operations proof limits are stated clearly; the 145-step crawl is useful rendered evidence, not a substitute for native, two-Mac or physical-device tests.

## Recommended plan edits

1. **Make batch 1 smaller to review and verify.** It combines two shared path-boundary changes with brand filesystem integrity and AI tenant authorization across separate domains. Keep the same priority, but split execution into a path-boundary checkpoint (O1/O2), then PO-1 and IA-3 as separate, small changes. This lets the shared resolver and export path protections be tested without coupling them to DB rename behavior or gallery promotion.
2. **Strengthen the brand mover acceptance.** In addition to initial complete-inventory preflight, require the mover to check the complete destination set before its first rename. Also exercise a move failure and ensure the caller cannot report a successful rename while DB paths and disk files disagree; current code catches/logs mover errors after committing DB changes. This avoids a partial move or swallowed failure at the exact data-safety boundary.
3. **Keep the O2 effect narrowly worded.** Describe it as escaped directory creation and image writes outside the server temp root for an authorized export account. State that the current client route's `keepBoth` avoids ordinary overwrite and escaped files are not returned in the zip. The root-contained runtime fix is still warranted.
4. **Clarify the PO concurrency mechanism.** The operations report says PO header updates currently have no `expectedUpdatedAt` check. The plan's “existing revision/conflict handling” should read as “reuse the established optimistic-update pattern/shared conflict UI where applicable; first verify which PO header/child writes need tokens,” rather than implying PO already has revision coverage. The plan already calls for validating coverage, so this is wording only.
5. **Change “This commit contains documentation only” to “This plan covers documentation-only audit work.”** At review time the master exists in the worktree but no commit has been made, so the current sentence is not yet a factual commit statement.

These are roadmap-quality improvements, not blockers to using the plan. Avoid expanding the plan with the static detector's warnings, unverified race hypotheses, hardware gaps, or the optional Import Preview behavior; its current exclusions are appropriate.
