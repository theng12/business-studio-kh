## RULES THAT COST US TIME

Each of these has already burned a session. They are instructions, not background.

- **Never `rm` anything.** Every removal is a move into `_trash/`; that folder is the owner's to empty and must not be tidied (AGENTS.md working rules).
- **Never bump `SCHEMA_VERSION` for additive work** (it is `2`; see `main/db/index.js`). A bump runs `wipeStructuralTables()` and wipes the catalog. New tables/columns use `CREATE TABLE IF NOT EXISTS` / `addColumnIfMissing`.
- **Never write a bare `ipcMain.handle`.** Register with `expose()` (client-reachable) or `exposeLocal()` (this Mac only); add a validator in `main/server/validators.js` or a written `EXEMPT` reason; proxy it in `main/client/index.js`; expose it on `main/preload.js`. `test/validatorCoverage.test.js` and `test/clientReachability.test.js` enforce this.
- **Do not restructure the three closed bulk modals** (`BulkBgRemovalModal`, `BulkOverlayRunModal`, `BulkProductsAIRunModal`), and do not rename the `watermarks` asset kind — AGENTS.md §25.
- **Get the app version from `app.getVersion()`, never `require('../../package.json')`** — that path does not exist in the packaged build (AGENTS.md §21, guarded by `test/buildHygiene.test.js`).
- **A version bump is two edits.** `package.json` alone ships a stale "What's new".
- **`Modal` focus belongs in an effect keyed `[open]` only.** Any other dependency re-focuses on each keystroke and breaks typing — the v0.1.69 one-letter bug.
- **The "which images" rule lives once in `main/util/imageScope.js` (`selectImages`).** One-based, position 1 = main; missing positions are skipped and reported, never failed. Do not re-implement it per operation.
- **Treat `graphify-out/` and the older status docs as stale until re-derived.** Source wins.
- **`npm test` mounts almost no React screens.** Rendered-UI bugs (a page that throws into the error boundary, a control that stops saving, a `$NaN` price) only show in the CDP crawl — run it for UI changes.
- **`test:native` must be rerun for DB work**; the pure-JS run reports `skip` and stays green, which hides a broken native path.
- **The web viewer can only reach Photos through iOS's own share sheet, and only over HTTPS — which this setup does not have, on purpose.** `navigator.share` needs a secure context, so on the viewer's plain-HTTP LAN / Tailscale address it does not exist at all, and the route is the native press-and-hold → Save Image. That missing share sheet is a **decision, not a bug** (AGENTS.md §25.4, 2026-09-27): the viewer already says "Open image to save" instead of "Save to Photos" and opens the result for the press. Never let a Files download be described as "saved to Photos" (v0.1.73, `webclient/index.html`).
- **`npm run dist` does not need the worktree on a topic branch, but `/Applications` does need the new build.** Install with `ditto` + `xattr -cr`, and move the replaced app into `_trash/` rather than deleting it (v0.1.73).
- **The owner looks for the DMGs in his own checkout, not in the build worktree.** `npm run dist` in the worktree writes them to `<wt>/dist`, and his `/Users/vengtheng/Developer/media-studio-kh/dist` stays empty — on 2026-09-26 he went looking and found nothing. Copy the release's DMG into his `dist/` as the last step of a release (one file since 2026-09-27), and verify with `shasum -a 256`; a release is not handed over until it is there (v0.1.74).
- **A file handed to iOS must be named and typed from the picture itself, never from the response's MIME label.** `serveAsset` (`main/server/index.js`) labels only jpg / jpeg / png / webp / svg and answers everything else with `application/octet-stream`; a File typed that way loses "Save Image" in the share sheet, and its subtype becomes the filename extension. `IMAGE_TYPE_BY_EXT` in `webclient/index.html` is the client-side table that mirrors it (v0.1.74).
- **A review handed to another agent is not a review it will keep to.** The 0.1.74 pass was asked for findings and edited the worktree instead; the edits were kept only because each claim was re-derived against the code, and one of them (a layout "defect") did not survive that. Ask for findings, then verify every one before taking it (v0.1.74).
- **Name the menu the user's platform actually has.** "Press and hold, then tap Save Image" is iOS; Android says **Download image**, and a desktop browser says Save image as…. An instruction pointing at a menu item that is not there is worse than no instruction — this shipped for two releases before a screenshot showed it on a Samsung phone (`IS_ANDROID`, `DEVICE_SAVE_MENU` in `webclient/index.html`, v0.1.75).
- **Do not assume the owner's devices are Apple.** The brother's phone is Android. Anything written for "the iPad" needs checking against that, including anything about Photos/Files/Downloads and share sheets (v0.1.75).
- **A price is read through `priceEntry` / `formatPriceEntry`, never off the column or the map.** The stored shapes are three: `priceRetail`/`priceWholesale` with their own currency columns, `prices[key]` as `{ amount, currency }`, and `prices[key]` as a bare number (rows written before v0.1.55). Reading the map as a scalar printed "$NaN" on a catalog once; the 0.1.79 audit found the same class of mistake in the label field list, the label canvas, the phone viewer, the catalog CSV and the bulk edit table. The rule lives in `main/util/prices.js`, is mirrored in `renderer/lib/prices.js` and in `webclient/index.html`, and `test/priceMirror.test.js` / `test/devicePriceMirror.test.js` / `test/pricePaths.test.js` fail when a copy drifts (v0.1.79).
- **A price token on an image is a bare number.** `{price_retail}`, `{price_wholesale}` and `{price_<group>}` all print the amount alone; the currency is the template's own text. A formatted group token beside a raw retail one on the same image was the inconsistency that started the audit (v0.1.79).
- **A new native test file is invisible until it is in the `test:native` list.** That script names its files one by one, so a fresh DB-backed test reports `skip` under `npm test` and looks green forever. 0.1.78 caught its own new file that way; check `package.json` whenever one is added.
- **Anything the phone downloads has to be under a served root.** The batch zip goes to `processed/overlay-zips/` precisely because `app-image://` and the server's asset route already cover `processed/` — a file written anywhere else is invisible to the device even though the desktop can read it (v0.1.78, pinned by `test/serverAssetTransport.test.js`).
- **A preview has to follow the choice it previews.** The phone's overlay preview composed onto the main image while the apply could be aimed at photo 2, so it showed the wrong picture with no hint that it had (fixed in v0.1.77 by giving `templates:renderPreview` a `position`). Whenever an action gains "which input", the preview needs the same argument in the same change.
- **Work on a branch, not `main` — even for a same-session feature.** Check `git branch --show-current` before the first `git add`. This has now happened twice: the 0.1.76 commit landed on `main` (caught before pushing, moved to `codex/web-batch-overlay`, `main` reset to `origin/main`), and the 0.1.85 commit landed on the build worktree's own `worktree/scratch` and was pushed there — an accidental remote branch that had to be deleted, with `worktree/scratch` reset to `origin/main`. Both times nothing was lost and `main` was never touched, but the check is one command and the rule is the reason it stays that way (v0.1.76, v0.1.85).
- **`display: flex` beats the `[hidden]` attribute.** A rule that sets `display` on an element makes `el.hidden = true` a no-op; the row gets marked hidden and still draws. Any newly hidden element needs its own `[hidden] { display: none; }` rule — `.reframe-row[hidden]` exists for exactly this (v0.1.75).
- **A delete holds the item in the recycle bin; the Trash is only for the final purge.** `main/deletedItems.js` snapshots the rows and RENAMES the files into `<dataDir>/.recycle/<id>/`, and `purge` (manual or the boot sweep) is what hands them to `main/util/fileTrash.js`. A new destructive path must hold before it removes anything, and a path that renumbers files afterwards (as image deletion does) must hold FIRST — a delayed move would take the wrong bytes (v0.1.86, pinned by test/deletedItemsWiring.test.js).
- **Anything that deletes must say what happens next, and it must be true.** The product and image confirms now name Settings → Recently deleted and how long the window is, because the earlier copy ("this cannot be undone") stopped being true the moment the bin existed. When the recovery story changes, the copy changes in the same commit — test/deletedItemsWiring.test.js fails if the screens stop pointing at the bin.
- **A delete in this app moves files to the Trash; it never erases them.** `main/util/fileTrash.js` asks Electron's `shell.trashItem`, and the database callers use `trashPathInBackground` (the row is already committed). If the Trash refuses a path, the files are **left where they are** — the helper must never fall back to `rm` while Electron is present, because an orphaned folder is recoverable and erased bytes are not. Only outside Electron (a `node --test` run, `ELECTRON_RUN_AS_NODE=1`, where no Trash exists at all) does it delete for real, so the native tests still catch a leak. When adding a new destructive path, follow both halves (v0.1.85).
- **A destructive action the user can reach by accident needs more than a red button.** Product deletion now sits in a `⋯` menu and its confirmation will not fire until the SKU (or `DELETE` for a batch) is typed — `requireText` on `ConfirmModal`, which keeps the confirm button disabled until the text matches. The owner's report was a product deleted by a click that was one button off; colour alone had already failed to prevent it (v0.1.85).
- **An account's name is looked up from the id, never copied onto a record.** `products`/`brands`/`categories`/`companies`.`updated_by_user_id` and `audit_log.user_id` store ids; the words come from the live users list (`users:listForAttribution`), and History falls back to **"Unknown user"** when the id no longer resolves. That is why a rename fixes the name on every past edit, and why deleting an account erases its name from its work while `users.setDeactivated` keeps it. Do not "preserve" a name by copying it into an audit row, and do not delete a user to disable them (v0.1.84, `main/db/users.js`).
- **A packaged build that exits 0 with only a `codesign_util.cc … task_name_for_pid` error is not broken — check `ELECTRON_RUN_AS_NODE` first.** This shell exports `ELECTRON_RUN_AS_NODE=1` globally, so running `/Applications/Media Studio KH.app/Contents/MacOS/Media Studio KH` directly makes the *Electron* binary behave as Node: it prints that one error, writes nothing to `crash.log`, opens no window and exits 0 — indistinguishable from a DMG that cannot launch. Always smoke-test an installed build as `env -u ELECTRON_RUN_AS_NODE "/Applications/Media Studio KH.app/Contents/MacOS/Media Studio KH"`. On 2026-09-27 this nearly produced a false "the DMGs are broken" report before the 0.1.83 install was verified to boot (`db:ready`, `window:shown`, footer 0.1.83).

- **List and grid views ask for a thumbnail; never draw a full photo at 36 px.** `appImageSrc(path, stamp, { w })` snaps `w` to 96 / 320 / 640 and both the local protocol and the server's `serveAsset` answer from `main/util/thumbCache.js` (sharp → WebP, `<userData>/thumb-cache/`, 256 MB cap, original on any failure). A new list/grid `<img>` should pass `w`; full-size viewers must not. The cache-clearing code only ever unlinks files matching its own name pattern in its own folder — it is app cache, not user data (v0.1.87).
- **Anything that rewrites a photo in place re-resolves it by row id + content hash after its last `await`.** Use `productImages.replaceImageFile` / `readImageNow` (main/ipc/images.js), and `setMainById` rather than `setMain(path)` after an await — a renumber in between hands the old path to a different photo. Adds, set-main, reorder and remove for one product are serialized by `withProductImageLock`; nothing inside the lock may take it again (v0.1.87).
- **`renumberFiles` never renames over a file it does not own.** It pre-checks every target slot and throws `RENUMBER_REFUSED` before moving anything; `reorder()` then rolls its order back so the database never shows a main image the files do not. Asset-folder collisions are compared case-insensitively and across companies (`assetDirIndex` in main/db/products.js), because the Mac's disk is case-insensitive (v0.1.87).
- **Never auto-delete a recycle-bin entry because its hold looks missing.** A moved data folder, a slow volume or a restored backup all look the same at boot. `dropOrphanedHolds` exists but is not called at boot; a missing hold makes Restore refuse with a plain message and the entry leaves by retention or by hand. Moving the data folder now carries `.recycle/` and `.merge-trash/` (`stageDataFolder`, main/ipc/settings.js) (v0.1.87).
- **Preview documents are not print documents.** `buildCatalogHtml` / `labelsDocument` with `preview: true` use `app-image://` URLs for photos and embed only the small Noto faces (Latin, Khmer, Thai); the 17 MB CJK faces are print-only (owner's choice, 2026-10-02). The CSP's `font-src 'self' data:` is what lets the preview iframe use them at all — before 0.1.87 previews silently used the Mac's own fonts (v0.1.87).
- **Agents' audit reports are leads, not facts.** In the 0.1.87 audit every finding was re-derived before fixing, one ("LabelGenerate does not reset its page") did not hold, and an independent second review of the data-safety change found a real regression (the boot sweep emptied Recently deleted after a data-folder move) that the author's own tests passed. Keep doing both.

- **Never run `gh pr merge --delete-branch` while that branch is checked out in a worktree.** gh 2.101 deletes the local branch by REMOVING the worktree it is checked out in — files, `node_modules`, `dist/` and the worktree's gitignored `_trash/` included, erased rather than trashed. On 2026-10-02 this took the build worktree and its `_trash/README.md` (the merged-branch log) with it; the branch half of that log was rebuilt from GitHub's PR history into the owner's `_trash/README-media-studio-kh-branch-log.md`, the free-text notes were not recoverable without Time Machine. Switch the worktree to `worktree/scratch` first and delete branches by hand. Re-creating the worktree is `git worktree add <wt> worktree/scratch`, `npm ci`, `npm run native:host` (npm 11 skips some install scripts; Electron downloads its binary on first use) (v0.1.87).
